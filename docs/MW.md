# Satima：微波 (MW)

> 這份是 **MW (微波輻射計)** 的詳細說明，內容來自原本的 Satima-MW。整合版的執行方式、資料列表、設定檔分層
> (`Satima.toml` + `Satima-MW.toml`)、介面語言、圖片模式 (native / dpi) 與極軌的接續判定請看 [README.md](../README.md)。
> 以下提到的設定，共同的幾節 (`[general]`、`[map]`、`[coastline]`、`[image]`、`[title]`、`[annotation]`、`[output]`…)
> 寫在 `Satima.toml`，MW 才有的寫在 `Satima-MW.toml`；任何一節都可以在 `Satima-MW.toml` 覆寫。
> 文中「原始解析度」的行為指 `[image] mode = "native"`；`mode = "dpi"` 時圖片大小改由 dpi 決定，取樣方式不變。


被動微波輻射計的亮溫影像：各頻道亮溫、PCT (極化修正亮溫)、37 與 85\~91 GHz 的 RGB 合成，NRL 與 RAMMB 兩種風格 (RAMMB 的 85\~92 GHz 是單頻道配色階)。
架構比照 Satima-GEO (設定檔、選單、地圖、存檔都相同)，差別在資料是極軌的「掃描帶」，取樣 (內插) 的核心重寫。

支援的資料：

| 層級 | 來源 | 儀器 |
|---|---|---|
| L1C | NASA PPS | GPM 星座所有輻射計：GMI、AMSR2、AMSR3、SSMIS、WSF-M MWI、MHS、ATMS… (同一種格式) |
| L1B | JAXA G-Portal | AMSR2 (GCOM-W1)、AMSR3 (GOSAT-GW)、GMI (GPM) |
| L1B | NOAA CLASS | SSMIS SDR / TDR (F16\~F19)、SSM/I SDR / TDR (F10\~F15) |
| L1 | NSMC | MWRI (FY-3B/C/D) |

## 執行

```
python Satima.py                   # 搜尋設定檔中 data_dir 的資料 
python Satima.py -d D:\data\mw     # 指定資料目錄
python Satima.py -f PPS-L1C        # 只找某個格式
python Satima.py -o D:\png         # 指定輸出目錄
python Satima.py --list            # 列出可用格式
```

流程：選資料 (可多筆) → 地圖投影 (Enter = MERC) → 地圖範圍 (南 北 西 東) → 產品 (可複選) → 色表 →
圖片寬度 (Enter = 原始取樣間距；`x3` = 3 倍；或直接輸入像素數)。

```
 1   GCOM-W1    AMSR2   L1C   2025/09/22 04:36-06:15Z   PPS   10 ch
 2   GOSAT-GW   AMSR3   L1C   2026/10/20 03:35-05:13Z   PPS   15 ch
輸入資料編號 (多筆可用 (3,5) 或 [1,3,5])：1
輸入投影編號 (Enter = MERC)：
地圖範圍 (南 北 西 東)：14 26 116 128
Products:
  Brightness temperature
     1.10.65V   2.10.65H   3.18.7V   4.18.7H   5.23.8V   6.23.8H   7.36.5V   8.36.5H   9.89V   10.89H
  PCT (polarization-corrected)
    11.PCT10.65   12.PCT18.7   13.PCT36.5   14.PCT89
  RGB
    15.NRL-37     16.RAMMB-37   17.NRL-89
輸入產品編號 (可複選，例如 13 17)：10 14 15 17
89H colormaps: 0.ALL 1.GRAY 2.NRL 3.NRL2 4.RAMMB 5.MWNRL
```

* 列表各欄：衛星、儀器、格式 (L1C / L1B / SDR / TDR…)、時間、**資料來源** (PPS、JAXA、CLASS、NSMC、EUMETSAT)、頻道數、
  備註 (多個檔自動接成一筆時的檔數，例如 ATMS 的 `21 檔`；中間有缺檔時 `19 檔 (缺 2)`)。
* **地圖範圍的輸入方式** (`[map] range_input`)：`"bounds"` (預設) 輸入「南 北 西 東」；`"center"` 同 Satima-PO，先輸入中心
  「緯度 經度」，再輸入範圍 (中心往外的緯度、經度各幾度；只輸入一個數字 = 兩者相同)，例如中心 `20 122`、範圍 `6` 就是 14\~26N、116\~128E。
  不論設哪一種，輸入 4 個數字都當成 南 北 西 東、輸入 2 個數字都當成中心，所以兩種可以隨時混用。
* 一個檔案是一段軌道 (整圈或半圈)，要自己知道哪一筆通過想看的地方；沒通過時會印 `[略過] 掃描帶沒有通過這個地圖範圍`。
* 圖片下方標註與檔名的時間是**掃描帶通過地圖範圍的時間** (範圍內各像素掃描時間的中位數)，不是檔案的起始時間。
* 選多筆時每筆各畫一張；產品依第一筆的選單選擇，其他筆依名稱 (89V、PCT89、NRL-37…) 對應，沒有的略過。
* 全球或整個洋區的大圖，`[map] resolution` 建議改 `"l"` (basemap 讀 `i` 以上的全球海岸線要數十秒)。

設定在 `Satima.toml` (共同) 與 `Satima-MW.toml` (MW 才有的與要覆寫的；UTF-8，可寫中文)；沒寫的項目用 `satima/core/config.py` 與 `satima/mw/config.py` 的預設值。
目錄 (`data_dir`、`output_dir`、`colormap_dir`) 可寫絕對或相對路徑；相對路徑以 Satima.py 所在目錄為準。
地圖投影 MERC / CYL / LCC、底圖 basemap / cartopy 的用法同 Satima-GEO (沒有全圓盤 FD)。

需要的套件：numpy、scipy、h5py、matplotlib、basemap 或 cartopy、mpkit (讀 .cmap 色表)；
numba 可省略 (有的話內插與存檔快數倍)。

## 產品

### 單頻道亮溫

每個頻道都可以畫；頻道名稱 = 頻率 + 極化，例如 `89V`、`36.5H`、`183.31±7V` (檔名中 `±` 寫成 `+-`)。
橫向掃描儀器 (MHS、ATMS) 的極化隨掃描角變化，標成 `QV` / `QH`。色表選單第 1 個固定是 GRAY
(`[gray]`：150\~300 K，冷為白)，其餘依頻率分組，定義在 `[colormap]`：

| 分組 | 頻率 | 預設色表 |
|---|---|---|
| `tb89` | 80\~95 GHz | NRL (`nrl89`，165\~280 K)、NRL2 (`89h`，105\~305 K)、RAMMB (`rammb89`，72\~323 K)、MWNRL (150\~320 K) |
| `tb37` | 30\~40 GHz | NRL (`37h`，125\~300 K)、MWNRL |
| `tb150` | 140\~200 GHz | NRL (`150h`，110\~310 K)、MWNRL |
| `tb` | 其他 | MWNRL、NRL37 |
| `pct89` / `pct37` / `pct` | PCT | NRL (`nrlpct` 160\~260 K / `37pct` 230\~280 K)、NRL2 (`89pct` 105\~280 K) |

`nrl89`、`nrlpct` 是原本 mpkit 裡的 NRL89、NRLPCT；`mwnrl` 是舊版 Satima-SSMIS 程式裡的色表；
`89h`、`37h`、`150h`、`89pct`、`37pct` 依 NRL GeoIPS (開源) 的色階定義製作。

`rammb89` 是 RAMMB/CIRA TC Realtime「85 – 92 GHz Brightness Temperature」產品的色階。RAMMB 的這個產品不是 RGB，
而是單頻道亮溫 (優先用水平極化，沒有水平極化的儀器才用垂直極化) 配色階，所以用法是選 `89H`
(SSM/I 為 `85.5H`、SSMIS 為 `91.665H`) 再選色表 RAMMB。RAMMB 沒有公開色階的數值，這裡是從成品圖的色條讀出來的
(2025/09/22 0505Z 樺加沙的 AMSR2 圖；色條標示 72\~323 K)：

| 亮溫 (K) | 70 | 160 | 225 | 265 | 280 | 300 | 325 |
|---|---|---|---|---|---|---|---|
| 顏色 | 白 | 紅 (255, 0, 0) | 深藍 (0, 50, 100) | 灰 (195, 195, 195) | 淺綠 (200, 255, 200) | 黃 (255, 255, 0) | 白 |

各點之間線性漸變，與色條逐像素相比平均差不到 1 階 (0\~255)，最大 13 階 (280\~290 K 一帶)。
RAMMB 另有 37 GHz、PCT 等產品 (見其說明頁)，但颱風頁面上看不到成品圖，無從取得色階，所以沒有做。

### PCT (極化修正亮溫)

`PCT = (1 + θ) × V − θ × H`：海面放射率低、V 與 H 差很多，PCT 把這個差異修掉，剩下的低值就是降水 / 冰晶散射。
同頻率同時有 V、H 的頻道才有 (PCT10.65、PCT18.7、PCT36.5、PCT89…)。θ 在 `[pct]`：

| 頻率 | 預設 θ | 出處 |
|---|---|---|
| 10 GHz | 1.5 | Cecil and Chronis (2018) |
| 19 GHz | 1.4 | 同上 |
| 37 GHz | 1.15 | 同上 (NRL 用 1.181，Lee et al. 2002) |
| 85\~91 GHz | 0.7 | 同上 (Spencer et al. 1989 為 0.818) |

### RGB 合成

配方全部寫在設定檔 `[rgb.<名稱>]`，可以自己改範圍或增加配方：`band` 指定頻率 (`tb37` / `tb89` …)，
三個色槍各取 `pct` / `v` / `h`，線性拉伸到 `range`，可 `inverse` (反相) 與 `gamma`。

| 名稱 | R | G | B | 出處 |
|---|---|---|---|---|
| NRL-37 | PCT37 (θ = 1.181) 260\~280 K 反相 | 37V 180\~300 | 37H 160\~300 | NRL GeoIPS `pmw_color37` (Lee et al. 2002) |
| NRL-89 | PCT89 (θ = 0.818) 220\~310 K 反相 | 89H 240\~300 | 89V 270\~290 | NRL GeoIPS `pmw_color89` |
| RAMMB-37 | PCT37 260\~280 K 反相 | 37V 160\~300 | 37H 180\~310 | RAMMB/CIRA TC Realtime 網頁說明 |

* 37 GHz：海面深綠、低層雲雨青色、深對流粉紅。89 GHz (NRL)：深對流紅色。
* RAMMB 的 85\~92 GHz 沒有 RGB 產品 (是單頻道配色階，見上面的色表 `rammb89`)；RAMMB-37 的數值出自其說明頁
  「Synthetic 37 GHz」一節對 color composite 的描述。
#### 任意頻道的配方 (探空儀用；試作)

上面的配方都要同一個頻率的 V、H。橫向掃描的探空儀 (ATMS、MHS、AMSU-A / B、SAPHIR) 沒有雙極化，所以另有一種
不寫 `band` 的配方：各色槍用 `channel` 直接指定頻率，可再用 `minus` 減掉另一個頻道。

```toml
[rgb.RGB-150]
red = { channel = "89", range = [220.0, 280.0], inverse = true }
green = { channel = "150", range = [180.0, 380.0] }
blue = { channel = "183±7", range = [200.0, 340.0] }
```

`channel` 取同一類頻率中最接近的頻道 (相差 12% 以內)：`"150"` 會對到 150 / 157 / 165.5 / 166 GHz，
`"183±7"` 對到 ±7 / ±6.6 / ±6.8 (MHS 的 190.31 GHz 也算 ±7)，`"89"` 對到 85.5 / 88.2 / 89 / 91.665；可加極化 (`"89H"`)，
沒寫時 H 優先。三個色槍的頻道都找得到才會出現在選單，所以有這些頻道的成像儀 (SSMIS、GMI、AMSR3) 也會列出。

預設附一個**試作**配方 `RGB-150` —— **不是 NRL / RAMMB 的官方配方**。NRL 在 2004 年有 AMSU-B 的「89 / 150 GHz 假色合成」
(Hawkins 等，AMS 26th Hurricanes 3D.2；2010 年的 AMSU-B 產品仍有 color)，但配方沒有公開；現行的 GeoIPS 對這些儀器只有單頻道產品。

| 名稱 | R | G | B | 觀感 | 適用 |
|---|---|---|---|---|---|
| RGB-150 | 89 GHz 220\~280 K 反相 | 150 GHz 180\~380 | 183±7 200\~340 | 比照 NRL-89：海面青綠、深對流紅 | ATMS、MHS、AMSU-B、SSMIS、GMI、AMSR3 |

* 紅色直接用 89 GHz：沒有極化修正，乾冷的海面 (中高緯度、乾空氣帶) 也偏冷，會泛紅 / 粉紅，和對流不易分辨。
  (改用兩個頻道的差可以避開，例如 `red = { channel = "89", minus = "150", range = [-20.0, 50.0] }`：只有冰晶散射才是正值。)
* 範圍是依樣本個案 (Humberto、辛樂克、Irma 等) 的亮溫分布訂的，可在設定檔調整。
* 配方用到故障的頻道時會顯示略過。

* 同一類頻率有多組 V/H 時 (WSF-M MWI 的 36.75 與 37.3 GHz) 取最接近標稱頻率 (37.0 / 89.0) 的一組。
* 85 GHz (SSM/I)、91.655 GHz (SSMIS) 都屬於 `tb89`。

## 內插 (`[swath] interpolation`)

微波的取樣很粗 (5\~25 km)，而且兩個方向的間距常常不同：

| 儀器 | 沿掃描 | 掃描線間距 | 比值 |
|---|---|---|---|
| WSF-M MWI | 4.3 km | 15.1 km | 3.5 |
| AMSR2 / AMSR3 89 GHz (只用 A 或 B) | 4.5 km | 10 km | 2.2 |
| GMI | 6.4 km | 13 km | 2.0 |
| AMSR2 / AMSR3 89 GHz (A/B 合併)、SSM/I 85 GHz、SSMIS 91 GHz | — | — | 約 1 |
| SSMIS 19 / 22 / 37 GHz | 25 km | 12.5 km | 0.5 (較粗的是沿掃描方向) |

每個輸出像素先換算成掃描帶中的小數座標 (第幾條掃描, 第幾個像素)：掃描帶的經緯度轉成單位球上的 3-D 座標
(不受換日線、極區影響)，用 KD-tree 找最近的取樣點，再以該點沿軌 / 沿掃描兩個方向的局部向量解出小數座標，
並以所在格子的雙線性曲面做牛頓修正。之後依設定取值：

| 設定 | 說明 |
|---|---|
| `"gauss"` (預設) | **高斯距離加權** (NRL 的做法)：像素值 = 周圍取樣點依實際距離的加權平均。各方向同樣平滑，取樣不對稱的儀器也不會有鋸齒 |
| `"cubic"` | 掃描帶索引空間的三次 Hermite (斜率加上限制，不會過衝)：保留沿掃描方向的細節，但取樣不對稱時斜向的結構呈鋸齒狀 |
| `"bilinear"` | 索引空間的雙線性內插 |
| `"nearest"` | **關閉內插**：每個取樣點畫成一塊，看到的是原始取樣 |

* 掃描帶以外、缺掃描處 (相鄰掃描的間距超過正常值 2.5 倍) 為無資料 (底色)，不會跨越缺口。
* 小數座標是輸出位置的平滑函數，所以只在每隔幾個像素的格子點上實際反算，其餘由格子點內插
  (間隔取到輸出像素不超過半個取樣間距為止；分條、多核心處理的結果與整張單核心逐像素相同)。
* 色表產品印出的「範圍內最低」是原始取樣值的極值，不是內插後的值。
* 內插只能讓畫面平順，不會增加解析度。

### 高斯距離加權 (`"gauss"`、`[swath] gauss_sigma`)

索引空間的內插 (cubic、bilinear) 兩個方向各自以相鄰的取樣點內插，取樣間距相近時效果很好；但間距相差很多時
(上表比值 2 以上)，眼牆、雨帶這類與掃描線斜交的結構在相鄰兩條掃描線上的位置差了好幾個像素，
內插卻是拿「同一個像素位置」的上下兩條掃描線來算，斜的邊界於是被畫成沿掃描線一段一段的鋸齒
(WSF-M MWI 的風眼最明顯)。這是沿掃描方向的細節比掃描線間距細、另一個方向取樣不足造成的，換更高階的內插也沒用。

NRL 的做法 (開源的 [GeoIPS](https://github.com/NRLMMD-GEOIPS/geoips)，NRL 熱帶氣旋網頁的微波產品即由它產生) 是
不在掃描帶上內插，而是在地理空間做高斯距離加權：

```
像素值 = Σ w·TB / Σ w        w = exp(−d² / σ²)，d = 取樣點到像素的距離
```

GeoIPS 的設定 (2026/11 查原始碼)：內插器 `interp_gauss` 呼叫 pyresample 的 `kd_tree.resample_gauss`
(每個像素取最近的 8 個取樣點)；`sigmaval` 在 89 GHz 單頻道、89pct、color89、37pct、color37 為 10000 m，
19 / 37 GHz 的 H、V 單頻道為 25000 m；影響半徑由各讀取器給 (AMSR2 89 GHz 10 km、GMI 12.5 km、SSMIS 影像頻道 15 km)；
熱帶氣旋圖的輸出格點為 1 km。各方向同樣平滑 (解析度統一到較粗的方向)，鋸齒自然消失。

Satima-MW 的 `"gauss"` 是同一個公式，有三點不同：

* **σ 可隨取樣間距調整**。`gauss_sigma = "x0.7"` (預設) = 該處較粗方向取樣間距的 0.7 倍：

  | 儀器 / 頻道 | 較粗方向的間距 | σ |
  |---|---|---|
  | WSF-M MWI | 15.1 km | 10.6 km |
  | GMI | 13 km | 9 km |
  | SSMIS 91 GHz | 12.5 km | 9 km |
  | SSMIS 19 / 22 / 37 GHz | 25 km | 17.5 km |
  | AMSR2 / AMSR3 89 GHz (A/B 合併) | 5 km | 3.5 km |
  | MHS、ATMS (橫向掃描) | 星下點 16 km，往邊緣變大 | 隨掃描位置變大 |

  NRL 固定用 10 km，對 MWI、GMI、SSMIS 91 GHz 大致就是 0.7 倍；但 AMSR 的 89 GHz 取樣 5 km，用 10 km 會糊掉很多，
  SSMIS 的 37 GHz 取樣 25 km，用 10 km 則會一顆一顆的。要與 NRL 相同可寫固定的公里數 `gauss_sigma = 10`。
  倍數越小越銳利：`"x0.5"` 時與掃描線斜交的窄雨帶會開始變成一串珠子。
* **σ 的 2.5 倍以內的取樣點全部計入** (不是只取最近的 8 個)。MWI 沿掃描 4.3 km 一點，最近的 8 個幾乎都在同一條
  掃描線上，鄰點的組合一變就有細微的不連續；全部計入才是完整的高斯平滑。取樣點由小數座標直接定位，
  不必對每個像素再查一次 KD-tree。
* **A / B 兩組掃描的取樣點一起加權** (AMSR 的 89 GHz)。

要知道的代價：

* 解析度降到較粗的方向，單點的極值會被拉平。例：MWI 89H 在樣本個案中原始取樣最低 109.3 K，`"x0.7"` 的影像最低
  146.7 K (固定 10 km 為 142.8 K)；AMSR2 89H (A/B 合併，σ 3.5 km) 110.1 → 121.7 K。
  「範圍內最低」仍以原始取樣值為準。要看沿掃描方向的細節用 `"cubic"`，要看原始取樣用 `"nearest"`。
* 只缺一個取樣點或一條掃描線時由周圍補上；離最近的有效取樣點超過較粗間距 1.05 倍的像素為無資料。
* CIRA / RAMMB 沒有公開他們微波影像的重取樣方式 (2024 年 AMS 的摘要只提到改為自行處理原始資料)，
  所以這裡只比照 NRL。

### 索引空間內插 (`"cubic"`、`"bilinear"`、`"nearest"`)

在小數座標所在的規則索引空間內插，兩個方向各自以真正相鄰的取樣點計算。

* `"cubic"` 是三次 Hermite，斜率加上限制 (單調)：內插值不會超出相鄰取樣值的範圍，眼牆、海岸這類銳利邊界
  不會出現過衝的假冷 / 暖環。
* 在取樣點的位置完全還原原值 (gauss 不會)。
* 周圍有無效值而算不出來的像素，自動退到較低階的方法 (cubic → bilinear → nearest)。
* SSMIS 的 19 / 22 / 37 GHz 沿掃描方向每 25 km 才一點，比雨帶窄的結構會呈現一顆一顆的樣子，這是取樣本身造成的。

### A / B 掃描合併 (`[swath] merge_ab`)

AMSR2、AMSR3 的 89 GHz 有 A、B 兩組饋源，各自沿軌 10 km 一條掃描；兩組在掃描帶中央相間 (合起來約 5 km)，
到邊緣則幾乎重疊 (兩者離軸角不同、掃描弧的半徑不同：樣本中 A 的掃描帶寬 1625 km、B 為 1599 km)，並不是固定的等間隔交錯。
`merge_ab = true` (預設) 時合併成一個頻道 `89V` / `89H`：A、B 各自算小數座標，沿掃描方向先在各條掃描線上內插，
沿軌方向再取 A、B 掃描線的**聯集**中離像素最近的上下各兩條內插，中央與邊緣都能正確處理。
(以上是索引空間內插的做法；`"gauss"` 時 A、B 的取樣點直接一起加權，不需要另外處理。)
`false` 時分列為 `89V-A`、`89V-B`、`89H-A`、`89H-B`。

SSM/I 的 85 GHz 也有 A、B 掃描，但兩者幾何相同 (同一個饋源)，讀取器直接依序交錯成 (2 × 掃描數, 128)。

## 多檔合併 (`[swath] merge`)

一次選到同衛星、同儀器、時間相接 (間隔不超過 `merge_gap` 秒) 的多個檔時，會詢問是否接起來畫成一張
(NASA 即時 L1C 每 10 分鐘一檔、JAXA L1B 半圈一檔、颱風剛好被切在兩個檔)。合併是沿掃描方向串接，
以掃描時間去掉重疊的掃描 (JAXA L1B 每個檔前後各多 30 條)，所以接縫處內插是連續的。
`merge = true` 直接合併、`false` 各畫各的。

ATMS 一個檔只有 32 秒，不走這個詢問：讀取器直接把同衛星、間隔 10 分鐘以內的檔接成一筆，列表的備註欄顯示檔數，
中間缺檔照樣接並標出缺幾個 (相鄰與否的門檻是檔案長度的一半，見 README「極軌的接續判定」)。
缺口處相鄰掃描的間距超過正常值，取樣時會留空，不會被內插抹平。

### ATMS 的定位檔

NOAA CLASS 的 `SATMS_*` (SDR)、`TATMS_*` (TDR) 只有亮溫，經緯度在對應的 `GATMO_*` (ATMS-SDR-GEO)。
讀取器以檔名中的「衛星_d日期_t起_e訖_b軌道」配對 (產製時間 `c…` 不必相同)，找不到定位檔的檔會略過並提示。取得方式：

* 在 CLASS 訂 ATMS SDR / TDR 時一併勾選 Geolocation (GATMO)；
* 或從 NOAA 的開放資料 (AWS S3，不需帳號) 下載，例如 NOAA-20：
  `https://noaa-nesdis-n20-pds.s3.amazonaws.com/ATMS-SDR-GEO/年/月/日/GATMO_j01_d…_t…_e…_b…_c…_oeac_ops.h5`
  (S-NPP 為 `noaa-nesdis-snpp-pds`、NOAA-21 為 `noaa-nesdis-n21-pds`；同一個 bucket 的 `ATMS-SDR/`、`ATMS-TDR/` 就是 SATMS、TATMS)。

CLASS 把定位與資料包成一個檔的 `GATMO-SATMS_*`、`GATMO-TATMS_*` 也列入支援 (資料集相同)，但沒有樣本、未實測。
SDR 與 TDR 的輸出檔名相同 (只差在資料列表的格式欄)，同一次執行兩種都畫時後者會蓋掉前者。

### AMSU-A

* 取樣很粗 (30 個視場，星下點 48 km、邊緣 130 km 以上)，颱風只看得出大致的結構；主要用途是 23.8 / 31.4 / 89 GHz 的大範圍分布
  與 50\~57 GHz 的溫度探空頻道 (暖心)。沒有雙極化，只有單頻道亮溫。
* 故障的頻道：有效取樣不到一半的頻道整個視為無資料 (樣本中 MetOp-B 的 89 GHz)；雜訊很大但仍有值的頻道照原樣顯示
  (樣本中 MetOp-B 的 54.4 GHz)。
* 一個檔是完整的一圈，高緯度的頭尾會重疊，重疊處取最近的取樣點，交界會有一條接縫。

## 新增格式

在 `sensors/mw/` 新增 `<儀器>-<格式>.py` (檔名要有 `-`)，寫一個繼承 `satima.mw.reader.SwathReader` 的類別，
最後一行 `READER = 類別名稱`：

| 項目 | 內容 |
|---|---|
| `NAME` `SENSOR` `DESCRIPTION` `PATTERNS` | 格式名稱 (= 檔名)、儀器、`--list` 的說明、檔案搜尋樣式 (glob) |
| `scenes(folder)` | 回傳 `Scene(衛星, 儀器, 起始時間, 結束時間, file=, orbit=, format=)` 列表，一個檔案一個 |
| `channels(scene)` | 回傳 `Channel(名稱, 頻率 GHz, 極化, 地理定位組, key=讀取器自用)` 列表 (選單順序)；名稱可用 `band_name(頻率, 極化, 偏移)` |
| `geo(scene, group)` | 回傳 `[Geo(lat, lon, 各掃描時間, 辨識用的 key)]`；A / B 掃描合併的頻道回傳兩個 |
| `tb(scene, channel)` | 回傳 `[亮溫陣列]` (K，float32，無效為 NaN)，個數與形狀對應 `geo()` |

其餘 (列表、選單、內插、PCT / RGB、繪圖、存檔、多檔合併) 都由主流程處理。

  |---|---|---|
  | AMSR2 | 低頻 (由 89A 推算) ≤ 2 m；89A / 89B 0 | +0.3 \~ +2.7 K (XCAL 校正量) |
  | AMSR3 | ≤ 4 m | −0.6 \~ +3.3 K |
  | GMI | 0 | 0.000 K (GMI 是 XCAL 的基準) |

**內插**
* 在取樣點位置取值：索引空間的三種方法都完全還原原值。
* 小數座標：取樣點來回誤差 0，格子中心來回誤差 < 1e-8；格子點內插與逐像素反算相比，中位數差 2e-6、最大 0.04 個取樣間距。
* numba 與 numpy 兩個版本的結果逐像素相同；分條 + 多核心與整張單核心的 8 位元影像逐像素相同。
* cubic 的內插值不超出原始取樣值的範圍 (89H：內插 110.32\~293.98 K，原始 110.12\~294.19 K)。
* gauss：WSF-M MWI (比值 3.5)、GMI、AMSR2 (A/B 合併與 37 GHz)、SSMIS、MHS 的樣本個案都沒有鋸齒與條紋；
  numba 與 numpy 兩個版本逐像素相同，分條與整張相同，值不超出原始取樣值的範圍，有值的像素與其他方法相同。
* 多檔合併：把一個檔切成重疊 80 條掃描的兩半再合併，與原檔完全相同；兩個相同的檔合併後等於一個檔。
  (樣本中沒有真正時間相接的兩個檔，未以實際的相鄰檔測試。)
